# Разработка

## Требования

- Node.js версии, совместимой с текущей версией Next.js.
- npm.
- Git.

## Установка и запуск

Из корня репозитория выполните:

```bash
npm install
npm run dev
```

Откройте [http://localhost:3000](http://localhost:3000). После изменения исходных файлов Next.js обновляет страницу автоматически.

Для остановки сервера нажмите `Ctrl + C`.

## Проверки

Перед созданием pull request выполните:

```bash
npm run lint
npx prettier --check .
npx tsc --noEmit
npm run build
```

Если Prettier сообщает о проблемах форматирования, исправьте их командой:

```bash
npx prettier --write .
```

Затем повторите проверки.

В проекте установлены ESLint, Prettier, Husky и lint-staged. Husky запускает `lint-staged` перед коммитом. Эта проверка форматирует изменённые файлы и запускает ESLint для изменённых JS/TS-файлов согласно конфигурации package.json.

Локальный hook не заменяет проверки GitHub Actions. Проверяйте результат workflow у каждого pull request.

## Тесты

Тестовый фреймворк пока не описан в зависимостях проекта. Перед добавлением тестов нужно выбрать и настроить инструмент, добавить команду запуска и сбор отчёта о покрытии, а затем подключить эти команды к CI.

Целевое покрытие для тестируемой логики: 100% statements, branches, functions и lines. Не исключайте файлы из покрытия без согласованной причины. Само число покрытия не заменяет проверку того, что тесты действительно проверяют поведение.

## Рабочий процесс

1. Обновите локальную ветку `main`.
2. Создайте отдельную ветку под одну задачу, например `feat/course-catalog` или `docs/project-guide`.
3. Внесите изменения, не смешивая несвязанные задачи.
4. Запустите проверки.
5. Создайте pull request в `main`.
6. В описании PR кратко укажите, что изменено и как проверено.
7. После успешных проверок и ревью объедините PR.

## Что указать в pull request

- Что сделано.
- Как проверить результат.
- Какие проверки запущены и прошли ли они.
- Скриншоты для заметных изменений интерфейса.
- Известные ограничения, если они остались.

## Команды Git

```bash
git switch main
git pull
git switch -c feat/short-task-name
# внесите изменения
git add .
git commit -m "feat: short description"
git push -u origin feat/short-task-name
```

После отправки ветки создайте pull request на GitHub.
