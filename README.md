# NOZO School

NOZO School — образовательная веб-платформа, которая помогает детям и взрослым с нарушениями слуха или зрения учиться в удобном формате.

Проект создаётся как портфолио-MVP. Сейчас это фронтенд-приложение: данные и пользовательские сценарии на этапе разработки могут быть демонстрационными. Реальный сервер, полноценная авторизация и отправка форм не входят в текущий объём MVP.

## Что планируется в MVP

- Главная страница с описанием платформы.
- Каталог курсов с поиском и фильтрами.
- Страница курса, модули, уроки и задания.
- Сохранение учебного прогресса в браузере.
- Демонстрационный вход и пользовательские страницы.
- Кабинет модератора: создание, редактирование и проверка курсов перед публикацией.
- Настройки доступности интерфейса и поддержка доступных учебных материалов.
- Адаптация интерфейса для мобильных экранов.

Оплата, чаты, видеозвонки, подбор вакансий и мобильное приложение в MVP не входят.

## Технологии

- Next.js
- React
- TypeScript
- Tailwind CSS
- SCSS
- Feature-Sliced Design (FSD)
- ESLint, Prettier, Husky и lint-staged

## Запуск проекта

Нужны Node.js и npm. Версия Node.js должна поддерживаться используемой версией Next.js.

```bash
git clone https://github.com/Pumovka/nozo_school.git
cd nozo_school
npm install
npm run dev
```

Откройте [http://localhost:3000](http://localhost:3000). Изменения в коде будут отображаться в браузере автоматически. Остановить сервер можно сочетанием `Ctrl + C`.

## Проверки перед отправкой изменений

```bash
npm run lint
npx prettier --check .
npx tsc --noEmit
npm run build
```

На данный момент в проекте настроены ESLint, Prettier, Husky и lint-staged. Тестовый фреймворк и проверка покрытия тестами должны быть настроены отдельно; не считайте тесты пройденными, пока они не добавлены и не запускаются в CI.

## Структура проекта

Основной код находится в `src/`. В рамках FSD код организуется по слоям:

- `app/` — маршруты, глобальные стили и настройки приложения.
- `pages/` — страницы и их композиция, если этот слой используется в выбранной структуре Next.js.
- `widgets/` — крупные самостоятельные блоки интерфейса.
- `features/` — действия пользователя.
- `entities/` — основные сущности предметной области, например курс и урок.
- `shared/` — общие UI-компоненты, утилиты и конфигурация.

Фактическую структуру и правила импортов см. в [документации по архитектуре](docs/ARCHITECTURE.md).

## Как вносить изменения

1. Создайте отдельную ветку под одну задачу.
2. Внесите изменения и проверьте их локально.
3. Создайте pull request в `main`.
4. В описании PR укажите, что изменено и как проверено.

Не добавляйте в MVP серверные функции или новые крупные направления без согласования объёма проекта.

## Статус

Проект находится в разработке. Перечисленные возможности — цель MVP, а не утверждение, что все они уже реализованы. Перед демонстрацией проверяйте, какие сценарии действительно работают в текущей версии.
